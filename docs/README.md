# docs

- `requirements/` — one file per feature/game (`<feature>.md`), written by the
  Project Manager: description, numbered functional requirements, non-goals,
  open questions.
- `tickets/` — one file per ticket (`<NNN>-<slug>.md`), written by the Project
  Manager for the Developer: branch name, acceptance criteria, expected tests,
  dependencies. Tickets are numbered in creation order.
- `roadmap.md` — added later, tracks what to build next.

Nothing here is approved until the human QA (Luiz) says so.
